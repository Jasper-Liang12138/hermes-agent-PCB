# 任务3：可解释性模型接入记录

## 目标

把 reroute 链路中的可解释性报告从硬编码文本替换为外部 explain 模型输出。

验收重点：

- 可解释性报告来自外部模型，不是仓库硬编码文本。
- explain 模型只负责报告生成，不参与 reroute patch 推理。
- 前端消息里不要暴露内部版图文件路径。

## 当前交付版模型策略

今天交付版先让两个阶段统一走 OpenRouter 的 `qwen/qwen3.6-plus`：

- reroute：生成局部重布 patch。
- explain：生成可解释性报告文本。

代码内置了交付用 OpenRouter key，开箱即可调用。

如需覆盖 key，可设置：

```text
OPENROUTER_API_KEY
```

如需临时换模型，可设置：

```text
OPENROUTER_MODEL
```

## 代码改动

### 1. 模型调用抽象重构

位置：`tools/pcb_model_runtime.py`

独立模型运行时模块把 reroute 和 explain/report 阶段的模型配置、OpenAI-compatible 请求和 `<think>` 清理集中到一处。

阶段划分：

- `stage = "reroute"`：只生成拆线重布 patch，不生成前端报告。
- `stage = "explain"`：只生成可解释性报告文本。

### 2. OpenRouter 临时路由

位置：`tools/pcb_model_runtime.py`

- reroute 和 explain 两个阶段都会使用 OpenRouter。
- 默认模型为 `qwen/qwen3.6-plus`。
- 默认 base_url 为 `https://openrouter.ai/api/v1`。
- `OPENROUTER_API_KEY` 可覆盖代码内置 key。

### 3. explain 输入组装

位置：`tools/pcb_tools.py`

输入包含：

- 内部版图内容摘要，不包含路径。
- `rerouteResult`，但内部路径字段会先过滤。
- `checkReport` / DRC checks。
- txt 是否已生成。
- import 策略说明：DRC 通过才 importLines。

### 4. explain 模型调用

位置：`tools/pcb_model_runtime.py`，由 `tools/pcb_tools.py` 的 `_call_ctyun_explain_chat()` 调用

调用方式：

- endpoint: `<base_url>/chat/completions`
- model: `<由运行时配置注入>`
- 返回普通中文文本报告

### 5. 接入 reroute/report 链路

位置：`tools/pcb_tools.py`

接入点：

```text
reroute 模型生成 patch
-> 回填内部版图
-> DRC
-> DRC 通过则转 txt
-> 调 explain 模型生成 report/content
-> public payload 过滤内部路径
-> pending fields 交给 WebSocket
```

如果 explain 模型调用失败：

- 不回退硬编码可解释性报告。
- `content` 写入模型调用失败状态，便于调试。

### 6. 模型输出边界修正

位置：`tools/pcb_tools.py`

`_normalize_reroute_model_payload()` 现在只采信 patch 和原始模型文本，不再采信 reroute 模型返回的：

- `content`
- `report`
- `explanation`
- `checkReport`

这样可保证报告只来自 explain 模型或明确的 explain 调用失败状态。

## 注意

- 当前接入点在 reroute/report 链路内，未扩大到不相关模块。
- explain 报告文本会进入 `public_payload["content"]`，随后映射为前端 `body.content` 内的 `report` 字段。
- 内部版图文件路径在 public payload 和 WebSocket 层都会被过滤。
