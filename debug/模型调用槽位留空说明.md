# 模型调用槽位说明

## 背景

当前仓库有两个外部模型调用阶段：

- reroute：用于生成局部重布 patch。
- explain：用于生成可解释性报告。

为了避免把 App Key、内部版图文件路径或训练数据相关细节写入协作记录，debug 文档只记录调用槽位、配置入口和链路行为。

## 当前交付版处理

位置：`tools/pcb_model_runtime.py`

- `stage = "reroute"` 保留为拆线重布模型调用槽位。
- `stage = "explain"` 保留为可解释性模型调用槽位。
- 两个阶段都会临时走 OpenRouter 的 `qwen/qwen3.6-plus`。
- 代码内置了交付用 OpenRouter key，开箱即可调用。
- 如需覆盖 key，可设置 `OPENROUTER_API_KEY`。

## 配置入口

当前交付版不需要额外配置。可选覆盖：

```text
OPENROUTER_API_KEY
```

可选模型覆盖：

```text
OPENROUTER_MODEL
```

阶段配置仍然保留：

```text
CTYUN_REROUTE_MODEL
CTYUN_REROUTE_BASE_URL
CTYUN_REROUTE_APP_KEY
CTYUN_EXPLAIN_MODEL
CTYUN_EXPLAIN_BASE_URL
CTYUN_EXPLAIN_APP_KEY
```

## 路径与数据原则

- debug 文档不写内部版图文件后缀。
- debug 文档不写 App Key。
- 前端消息不暴露内部版图文件路径。
- 过程性中间文件只用于运行时链路，不作为前端公开内容。
- 模型原始输出和 patch 默认不落盘；需要本地诊断时再显式开启调试开关。

## 验证

新增或保留的测试应覆盖：

- 前端输入会在内部转换为模型需要的版图表达。
- 模型 prompt 不包含内部文件路径。
- reroute 和 explain 阶段读取不同配置槽位。
- 两个阶段都走同一个临时模型。
- debug 目录中不出现内部版图文件后缀文本。
